Financial Review Report

Inventory → Sales Invoice / POS Flow & Out-of-Stock Invoicing
Project: Operix (Flutter Desktop, PostgreSQL)  |  Date: 2026-06-16  |  Reviewed by: Senior Finance Consultant (AI)

Executive Summary

The purchase → inventory → sell flow is sound: a received product immediately surfaces in both the sales-invoice picker and the POS grid, because both read the live products table. Invoicing an out-of-stock inventory item is blocked at save — which is financially correct (it prevents negative inventory and invalid COGS). Two UX/accounting gaps are worth addressing: the sales-invoice picker lets you add an out-of-stock item before failing at save, and positive stock adjustments post no GL and carry no cost.

Detailed Findings

✅ Correct  Out-of-stock invoicing is blocked at save — by design

The sales-invoice picker lets you select a zero-stock product (stock just shows red), but on Save the repository guard (_assertStockAvailable + UPDATE … WHERE quantity_on_hand >= quantity RETURNING cost_price in postgres_sales_invoice_repository.dart) throws "Not enough stock to invoice X." POS blocks earlier still (pos_controller.dart:101 / pos_terminal.dart:421). Allowing it would create negative inventory → negative/zero COGS → misstated gross profit and an Inventory balance that can't tie to a physical count. The block is the financially-correct default.

To invoice an out-of-stock item — raise on-hand first

A. Purchase invoice (recommended): receives stock with cost + GL — the flow above.   B. Stock adjustment (Inventory → Stock Movements → positive delta): quick, but see the finding below — no GL, no cost.   C. Service / non-stock line: a line with no product id isn't stock-guarded (needs a "custom line" feature; the picker doesn't offer it yet).

⚠️ Risk  Picker lets you add an out-of-stock item, then fails only at save

_ProductPickerDialog (operix_dashboard.dart:2801) returns zero-stock rows as tappable; the user builds the invoice and only learns it's blocked at save time. POS handles this correctly by disabling the tile up front. Inconsistent and confusing.

Recommendation — Medium

Mirror POS: disable (or visibly flag) rows where quantityOnHand <= 0 in the picker, or show an inline "out of stock — restock first" warning when added, so the failure is surfaced before save.

❌ Wrong  Stock adjustments post no GL and carry no cost

postgres_stock_repository.dart:54 (adjust()) updates quantity_on_hand and logs a movement, but posts no journal entry and sets no cost. Consequences: (1) a positive adjustment raises quantity with no matching Inventory (1300) debit → the Inventory GL drifts from the subledger; (2) units brought in this way carry the product's existing cost_price (often 0 for a never-purchased item), so they later sell at zero COGS, overstating gross profit.

Recommendation — High

Post adjustments to the GL: Dr/Cr Inventory (1300) against an Inventory Adjustment / Shrinkage (gain–loss) expense account, valued at the product's cost; for opening-stock receipts, capture a cost on the way in (and weight it into cost_price). Block zero-cost positive adjustments on items with no cost set.
